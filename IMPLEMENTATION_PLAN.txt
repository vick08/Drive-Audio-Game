IMPLEMENTATION PLAN: NATIVE MACOS PORT OF DRIVE (2002)

1. OVERVIEW AND ARCHITECTURE GOALS

Target Deliverable:
A standalone, native macOS application bundle (Drive.app) written in Swift using AppKit and AVAudioEngine/CoreAudio, running natively on Apple Silicon and Intel Macs with zero external runtime dependencies.

Core Preservation Requirements:
- 100% of original self-voicing accessibility (all menu prompts, tutorials, co-pilot callouts by Leo and Eve, sound effects, and spoken score readouts).
- 100% of original keyboard navigation and gameplay controls (Up/Down/Left/Right arrows, Spacebar, Return/Enter, Escape, and A-Z/Backspace for high-score name entry) with no macOS system alert beeps.
- Sample-accurate reproduction of the CPS (Bonneville) real-time modular audio synthesis and mixing graphs across all 5 Director movies (intro.dxr, menu.dxr, game.dxr, score.dxr, quit.dxr), including the real-time 5-gear procedural shuttle motor synthesizer in game.dxr.
- Direct loading of the original 249 uncompressed RIFF WAVE (.hrs) audio assets and 2 splash screen JPEGs (pics/cover6.jpg and pics/cdsplash.jpg) without modifying the original asset files.


2. CRITICAL TECHNICAL INVARIANTS TO ENFORCE

Invariant 1: Real-Time Procedural Motor Synthesis (game.dxr Script #7)
The Shuttle motor sound has no .hrs audio file; it is synthesized procedurally in CPS using a 1024-sample 5-harmonic wavetable ("harm 1024 1 0.2 0.1 0.05 0.02" in table83) driven by three oscillators (oscil161, oscil163, oscil166), modulated by sinus172, arand171, upsamp160, and upsamp169, with 5-gear transmission switching logic (switch78, switch155, switch157) across speed thresholds 100, 200, 300, and 399. All 25 CPS node types used by the game must be implemented in our audio graph engine.

Invariant 2: Preserving Empty Indices for Missing .hrs Files in audioFromDisk
Cross-referencing the Lingo scripts against disk files showed 12 referenced .hrs filenames that do not exist on disk (menu/eve02.hrs, menu/eve53.hrs, doppler/heliall.hrs, eve/eve23.hrs..eve27.hrs, eve/nog3.hrs, eve/nog35.hrs, interface/startsample.hrs, leo/leo92.hrs). Because CPSDistr.exe assigns 0-based slot numbers sequentially for every "conv=<filename>" call regardless of whether the file exists on disk, our audioFromDisk node must preserve slot indices for missing files and treat them as silent no-ops when triggered. Skipping them would shift all subsequent voice prompts by one or more indices.

Invariant 3: Sample-Completion Trigger Chains (score.dxr Script #0 & Script #16)
Spoken multi-word numbers in score.dxr rely on output pin 40 of audioFromDisk firing an end-of-sample trigger through button, ==, float, and order nodes to start the next spoken number word cleanly after the previous word finishes.

Invariant 4: Mixed Audio Sample Rates and Channels
The 249 .hrs WAV files include 44.1 kHz stereo, 44.1 kHz mono, 22.05 kHz stereo, and 16 kHz mono files. The audioFromDisk node must advance its fractional readhead by (fileSampleRate / 44100.0) * playbackRate (pin 21) and output mono files on pin 30 and stereo files on pins 30 (left) and 31 (right).

Invariant 5: Local High-Score Storage Replacing Offline 2002 PHP Endpoints
The original game passes the latest run score via Xtras/sdata and then queries http://www2.hku.nl/~audiogam/drive/score2/dirscore.php3, score.php3, and name.php3. Because that server is permanently offline, the port will retain local sdata file compatibility and replace the HTTP calls with local persistent storage (initialized to the original default high score of 53700 by "sander" from STXT cast members 298 and 303), preserving the spoken high-score comparison and A-Z keyboard name entry flow.


3. PHASE-BY-PHASE IMPLEMENTATION TASKS

TASK 1: Complete Decompilation and Score Timeline Extraction
Objective: Extract a 100% complete, human-readable specification of all scripts, frame timelines, cast members, and CPS patches from the five .dxr files and CPSDistr.exe.
Steps:
1.1. Enhance the Python Lingo disassembler/decompiler in the scratch directory to properly decode 4-byte float literals (opcode 0x71 / 0xf1) and reconstruct high-level Lingo statements for all 103 active Lscr script chunks across intro.dxr (4), menu.dxr (21), game.dxr (29), score.dxr (45), and quit.dxr (4).
1.2. Parse the VWSC (Score timeline), VWLB (frame labels), VWFI (movie tempo/frame rate), CAS*/CASt (cast member tables), and STXT (text field cast members) chunks for all 5 movies to map exact frame numbers to frame behaviors and sprite scripts.
1.3. Disassemble the node evaluation methods in Xtras/CPSDistr.exe for all 25 CPS node types to confirm exact pin numbering (10, 11, 20, 21, 22, 23, 30, 31, 40, 41) and control/audio signal flow.
Deliverable: A verified decompiled specification and structured JSON/Swift data definitions for all 5 movies.

TASK 2: Native macOS CPS Modular Audio & DSP Engine
Objective: Implement the CPS audio engine in Swift using AVAudioEngine and AVAudioSourceNode running at 44,100 Hz stereo float32.
Steps:
2.1. Implement the WAV (.hrs) loader and cache manager capable of reading 16-bit PCM mono/stereo WAV files at 16 kHz, 22.05 kHz, and 44.1 kHz, normalizing Windows backslash paths to macOS forward slashes, and preserving placeholder slots for missing files.
2.2. Implement all 25 CPS node types:
  - Audio generators & I/O: audioFromDisk, audioOut, table ("harm ..."), oscil, sinus, arand, upsamp, fader
  - Control & state nodes: numberField, constant, float, button, order, switch
  - Math & logic operators: +, -, *, /, pow, exp, ==, <=, >=, >, &&
2.3. Implement the Lingo Xtra bridge API:
  - CPSgetObject(typeName) -> Int
  - CPSOBJConversate(nodeId, commandString)
  - CPSgetConnection(srcId, srcOutPin, dstId, dstInPin)
  - CPSOBJkin(nodeId, value, inPin)
  - CPSstartAudio(), CPSstopAudio(), CPSxtra("cleanAll")
2.4. Write a standalone CLI test harness to load the CPS patches from intro, menu, game, score, and quit and verify audio rendering and motor synthesis across speeds 0..800.
Deliverable: CPSAudioEngine.swift module verified by automated audio graph tests.

TASK 3: macOS AppKit Windowing, Frame Scheduler, Keyboard Input & Accessibility Shell
Objective: Create the native macOS application shell, Director-compatible frame scheduler, keyboard manager, and accessibility layer.
Steps:
3.1. Create the 800x600 NSWindow and custom NSView that displays pics/cover6.jpg (during Intro/Menu/Game/Score) and pics/cdsplash.jpg (during Quit), plus optional high-contrast visual telemetry (current screen, speed, boosters, score) for sighted or low-vision users.
3.2. Implement the Director frame clock (enterFrame / exitFrame / startTimer / the timer) matching each movie's VWFI tempo.
3.3. Implement full keyboard event handling (keyDown, keyUp, flagsChanged) tracking Director keyCodes (126 Up, 125 Down, 123 Left, 124 Right, 49 Space, 36 Return, 53 Escape) and character keys, overriding performKeyEquivalent and keyDown so macOS never plays system alert beeps on arrow/space/letter presses.
3.4. Expose NSAccessibility properties on the main view so VoiceOver users can query window state if desired, while ensuring the game's built-in self-voicing works seamlessly without requiring a screen reader.
Deliverable: AppShell.swift and DirectorRuntime.swift modules.

TASK 4: Porting Intro, Menu, and Quit Movies (intro.dxr, menu.dxr, quit.dxr)
Objective: Implement the state machines and CPS patches for the Intro, Menu, and Quit screens.
Steps:
4.1. Port intro.dxr: Initialize the intro CPS graph (start/start.hrs), run the 36-second timer (2160 ticks at 60 ticks/sec), and transition to menu.dxr on completion or when Spacebar is pressed.
4.2. Port menu.dxr: Initialize the menu CPS graph (menu/intro.hrs loop, sampler1 for eve01..eve11 voice prompts, sampler2 for snd1..snd3 UI SFX), implement menuomlaag, menuomhoog, menutext, checkding, enterding, music fade-in/fade-out, and navigation to Game, Tutorial/Instructions, High Score, or Quit.
4.3. Port quit.dxr: Display cdsplash.jpg, play quit/quitmix.hrs via CPS, and terminate the application cleanly when the audio finishes or Spacebar is pressed.
Deliverable: IntroMovie.swift, MenuMovie.swift, and QuitMovie.swift modules.

TASK 5: Porting Core Gameplay Movie (game.dxr)
Objective: Implement the full gameplay loop, 219-node CPS audio graph, and all 28 Lingo handlers in game.dxr.
Steps:
5.1. Port Script #7 (the 219-node CPS patch) and Script #8 (initial volume/parameter configuration).
5.2. Port Script #28 and frame scripts #0..#27:
  - Acceleration and deceleration physics (SpeedUp, SpeedDown, gSpeed, gCurSpeed, gAccel, gStroop).
  - 5-gear transmission and speed thresholds (ShiftCheck, ShiftDwn, gConSpeed99..gConSpeed799).
  - Anti-key-hold protection (CapLock, CaplocTime) requiring rapid tapping or proper timing as in the original.
  - Braking mechanics (Rem, BreakStop, metaalrem.hrs).
  - Booster zones, capture (Left arrow, up to 3 boosters), activation (Right arrow), and scoring (BoAanloop, BoInside, BoCapture, BoActivate, BoAfloop, BoNone, BoScore).
  - SoundWarp zones (SWAanloop, SWInside, SWAfloop) and environmental/doppler events (EventCheck, EventAfloop, InterCheck).
  - Co-pilot Leo and Eve commentary state machines (Bijder, KotsRuler, CheckPoint, TimeAder, EndCheck).
5.3. Save final score to sdata and transition to score.dxr (or menu.dxr on Escape).
Deliverable: GameMovie.swift module.

TASK 6: Porting Score Readout, High-Score Persistence & App Bundle Packaging (score.dxr)
Objective: Implement the spoken score readout, high-score comparison, accessible keyboard name entry, and final macOS .app bundle packaging.
Steps:
6.1. Port score.dxr Script #0 (CPS spoken score readout graph with cScore1..cScore7) and Script #16 (thousands/hundreds decomposition via gDuizend and gHonderd using score/cijf*.hrs).
6.2. Implement local high-score persistence (storing high score and holder name in Application Support / local JSON, initialized to 53700 by "sander") to replace the offline 2002 PHP scripts (dirscore.php3, score.php3, name.php3).
6.3. Port the spoken high-score comparison ("eigen score", difference calculation lVerschil) and the interactive spoken A-Z keyboard name entry flow when a player achieves a new high score.
6.4. Assemble the complete macOS application bundle (Drive.app) with Info.plist, executable binary, and linked/bundled Xtras and pics resources.
Deliverable: ScoreMovie.swift module and runnable Drive.app bundle.
